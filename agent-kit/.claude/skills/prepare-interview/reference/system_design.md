# System design

## What it evaluates

Requirements gathering, high-level design, data model, scaling, trade-offs, failure modes, observability. Seniority shows in the trade-offs.

## Typical questions

- Design a URL shortener / payment ledger / notification system / feed.
- How does it scale to 10× / 100×?
- What happens when this component fails?
- Where is the bottleneck? How would you measure it?

## Traps

- Drawing boxes before asking functional and non-functional requirements.
- Name-dropping technologies without justifying them.
- Never talking about consistency, idempotency or failures.
