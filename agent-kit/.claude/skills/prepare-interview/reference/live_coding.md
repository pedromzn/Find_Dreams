# Live coding

## What it evaluates

Problem solving out loud, communication, clean code under time pressure, testing your own code, handling hints.

## Typical questions

- An algorithmic or practical problem (parse, aggregate, rate limiter, LRU cache…).
- 'How would you test it?'
- 'What is the complexity? Can you do better?'
- A follow-up that changes a requirement.

## Traps

- Coding in silence.
- Jumping to code before clarifying inputs, outputs and edge cases.
- Ignoring the interviewer's hints.
- Not running through an example at the end.
